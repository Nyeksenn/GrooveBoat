# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

GrooveBoat is a GTK4/libadwaita desktop music player for Subsonic-compatible servers, written in Java 25 using [java-gi](https://github.com/jwharm/java-gi) bindings (GTK, Adw, GStreamer, libsecret). Metadata is cached locally in an H2 database via Ebean ORM; audio is streamed from the server into a GStreamer pipeline.

## Commands

```sh
./gradlew run                 # build + run (adds --enable-native-access=ALL-UNNAMED)
./gradlew build               # compile everything
./gradlew generateMigrations  # generate a new Ebean DB migration from entity changes
./install_settings.sh         # install + compile the GSettings schema (sudo, required once / after schema changes)
```

- `classes` depends on `compileResources`, which first runs `compileSass` (`sass` CLI: `scss/main.scss` → `css/main.css`) and then `glib-compile-resources` to produce `src/main/resources/grooveboat.gresource`. Both `sass` and `glib-compile-resources` must be on PATH.
- `Main` loads the gresource via the relative path `src/main/resources/grooveboat.gresource`, so the app must be run from the repo root.
- The GSettings schema `io.github.Nyeksenn.grooveboat` (keys: `username`, `url`, `last-sync`) must be installed system-wide or `new Settings(...)` will abort the app.
- There is no test suite; `src/test` only holds `MigrationGenerator` (used by `generateMigrations`).

## Architecture

Detailed architecture docs live in `docs/` (start at `docs/README.md`). Summary:

**Startup (`Main`)**: configures the default Ebean `Database` (H2 file at `$XDG_DATA_HOME/grooveboat/cache`, migrations auto-run from `resources/dbmigration/h2`), registers the gresource bundle, registers every templated widget / custom GObject type, then runs `GrooveboatApp`.

**Adding a UI component** requires touching three places: a `.ui` template in `resources/templates/`, an entry in `grooveboat.gresource.xml` (alias = path under `/io/github/Nyeksenn/grooveboat/`), and a `TemplateTypes.register(...)` (or `Types.register(...)` for non-template GObjects) call in `Main`. Widget classes use `@GtkTemplate`, `@RegisteredType`, `@GtkChild(name=...)`, `@GtkCallback`, `@InstanceInit`, and must keep a `(MemorySegment address)` constructor. New icons likewise need a gresource entry under the `icons/scalable/actions/` prefix.

**`GrooveboatApp`** (Adw `Application`) is the central hub that widgets reach via `getRoot()` → window → `getApplication()`. It owns:
- `subsonic` (`client.Subsonic`) — the facade over `SubsonicClient` (raw HTTP/Jackson calls, auth, cover-art caching to `$XDG_DATA_HOME/grooveboat/covers`). `Subsonic` syncs remote data into the DB: `refreshRemoteData` does incremental album sync keyed on the `last-sync` setting (full refresh truncates tables via `Helpers.truncateDB`); `getSongs` lazily fetches/upserts an album's songs.
- `pipeline` (`audio.AppPipeline`) — a GStreamer pipeline `appsrc → decodebin → audioconvert → audioresample → autoaudiosink`, running its own `MainLoop` on a dedicated thread (`gstExec`). Bus messages (EOS, errors, state changes) are handled in `GrooveboatApp.handleBusMessage`.
- `stream` (`gobjects.MediaSubsonic`, a GTK `MediaStream` subclass) — one per playing song; pulls the HTTP stream from `Subsonic` and pushes buffers into a fresh `AppSrc`, handles seeking (re-requesting the stream at an offset) and position updates via the `scheduler`.
- `queueStore` (`audio.QueueStore`, a GObject) — the play queue (`ListStore<SongListItem>` + `SingleSelection`). Changing the selection closes the old stream, creates a new one and emits the `initialize-song` signal that player widgets (`MusicPlayer`, `MiniPlayer`, `MusicControls`) listen to. Queue manipulation is exposed as GActions (e.g. `queue-song`, `play-next`, `toggle-play`).
- `executor` / `scheduler` thread pools for background work; long-running work (network, DB) must stay off the GTK main thread.

**Data layers** (keep them distinct):
- `deserializer/` — Java records mirroring Subsonic JSON responses (Jackson 3, `tools.jackson.*`).
- `entities/` — Ebean entities (`*Model`, extending `BaseModel`) persisted in H2; query beans (`entities.query.Q*Model`) are generated by the `querybean-generator` annotation processor. After changing entities, run `generateMigrations` and commit the new files in `resources/dbmigration/`.
- `gobjects/` — GObject wrappers (`AlbumListItem`, `SongListItem`, `QueueListItem`) used as items in GTK list models, plus custom GObjects (`RoundedImage`, `MediaSubsonic`) and `SecretKeeper`.

**Credentials**: server URL and username live in GSettings; the password is stored in the system keyring via libsecret (`SecretKeeper` singleton, `COMPAT_NETWORK` schema). First-run setup is the `SetupDialog` flow (`WelcomePage` → `ConnectionPage` → `CredentialsPage`).

**Styling**: edit `resources/scss/main.scss`, not the generated `css/main.css`; it's loaded from the gresource at `/io/github/Nyeksenn/grooveboat/main.css`.
